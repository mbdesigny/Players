# برومبت تنفيذي — تحسين شامل لتطبيق «أُنس · Ouns»

> انسخ كامل هذا المستند إلى وكيل برمجي (coding agent) ونفّذه على مستودع المشروع.

## 0) الدور والسياق

أنت مهندس واجهات أمامية ومسؤول جودة في مشروع **أُنس (Ouns)** — مشغّل قرآني عربي RTL أولاً مبني على **Astro** (مخرج ثابت) + **وحدة JavaScript عادية واحدة** بلا أي إطار عمل في المتصفح. المنطق كله في `src/scripts/app.js`، والتنسيقات في `src/styles/global.css`، والهيكل في `src/pages/index.astro` ومكوّنات `src/components/*.astro`.

مهمتك شاملة على مرحلتين:
- **المرحلة أ**: إصلاح العيوب التقنية والهندسية المذكورة أدناه.
- **المرحلة ب**: تنفيذ تعديلات تجربة الاستخدام والتجاوب المطلوبة.

نفّذ كل بند فعلياً في الكود، ووثّق ما غيّرته، ولا تكتفِ بالاقتراحات.

---

## 1) قيود وسياسات إلزامية (لا تُخالَف)

- أبقِ المشروع **Astro ثابتاً + JS عادي**؛ لا تُدخل React/Vue/Svelte ولا أي إطار عمل ثقيل.
- **RTL أولاً** ودعم كامل للعربية والإنجليزية، وبقاء التبديل بين الوضعين (light/dark) عاملاً.
- لا تكسر أي ميزة قائمة (المشغّل، المفضلة، التنزيلات، مؤقّت النوم، المصحف، المواقيت، الأذكار، تلاوات يوتيوب).
- حافظ على مفاتيح `localStorage` المبدوءة بـ `ouns_` وقيمها، وأضف مفاتيح جديدة بنفس النمط بدل تغيير القديمة.
- استعمل `esc()` لأي بيانات قادمة من API قبل إدراجها عبر `innerHTML`.
- أبقِ البناء أخضر: `npm install && npm run build` يجب أن ينجح دون أخطاء.
- لا تُجرِ تخمينات: تحقّق من السلوك الفعلي (شغّل المشروع وافحص) قبل الإصلاح، ووضّح أي افتراض.

---

## 2) خريطة مرجعية سريعة

- المنطق: `src/scripts/app.js` (≈1468 سطر).
- التنسيقات: `src/styles/global.css` (≈4550 سطر، وفيه تكرار ناتج عن ترحيل Astro).
- الهيكل: `src/pages/index.astro`, `src/layouts/Base.astro`, `src/components/`.
- الأصول: `public/` (service worker `public/sw.js`، manifest، offline).
- البيانات: `src/data/adhkar.json`, `src/data/live.json`.
- الإعداد: `astro.config.mjs`, `package.json`.

# المرحلة أ — إصلاح العيوب

## A1. إعداد النشر غير مكتمل
- **المشكلة**: `astro.config.mjs` يشير إلى نطاق Cloudflare Workers (`ounsapp.musbch.workers.dev`) لكن لا يوجد محوّل (`@astrojs/cloudflare`) ولا `wrangler.jsonc/toml` ولا أي CI.
- **المطلوب**: اختر مساراً واحداً واضحاً ووثّقه في README: (أ) نشر Workers مع إضافة `@astrojs/cloudflare` وملف wrangler، أو (ب) نشر استاتيكي على Cloudflare Pages مع خطوة build. أضف ملف إعداد فعلي وخطوات نشر قابلة للتكرار.
- **القبول**: يوجد إعداد نشر صالح + تعليمات واضحة، والبناء ينتج نشراً عاملاً.

## A2. اعتماد صفحات المصحف على GitHub raw (هشّ)
- **المشكلة**: في `app.js` (‏`MUSHAF_REMOTE`) تُجلب 602/604 صفحة حفص و604/604 ورش من `raw.githubusercontent.com` مباشرة (لا CDN)، وهذا عرضة لحدود المعدّل والحجب والبطء، كما أن GitHub raw قد يخدم `.svg` بـ `Content-Type: text/plain` مع `nosniff` فيمنع عرضها داخل `<img>`.
- **المطلوب**:
  1. تحقّق عملياً من عرض الصفحات البعيدة داخل `<img>` في المتصفح، ووثّق النتيجة.
  2. انتقل إلى مصدر/CDN موثوق مع تخزين مؤقّت مناسب، وإن تعذّر ذلك فأضف طبقة وسيطة للتخزين المؤقّت.
  3. **أضف احتياطي PNG لرواية ورش** — حالياً `data-png` يُضبط فقط عندما `rw==='hafs'`، فتفشل صفحات ورش بلا بديل.
- **القبول**: لا صفحة من 1..604 (حفص وورش) تنتهي مكسورة؛ ويوجد مسار بديل عند فشل المصدر الأساسي.

## A3. خطر انهيار الذاكرة في «تحميل جميع الصفحات»
- **المشكلة**: `mushafZipAll()` يحمل 604 ملف SVG كاملة في الذاكرة ثم يبني `Blob` ضخماً (تقديراً 100MB+).
- **المطلوب**: اجعل التوليد تدفقياً (streaming) أو قسّمه إلى أجزاء/دفعات، وأضف مؤشر تقدّم واضحاً وإمكانية الإلغاء، وحدوداً للأمان.
- **القبول**: تنزيل 604 صفحة يكتمل على جهاز هاتف دون انهيار ذاكرة.

## A4. خطر فشل تشغيل الصوت بسبب CORS
- **المشكلة**: `audio.crossOrigin='anonymous'` مع تمرير الصوت عبر Web Audio (`ensureAnalyser()`) يعني أن أي خادم لا يرسل ترويسات CORS سيفشل تحميله بالكامل.
- **المطلوب**: تحقّق من سلوك مصادر mp3quran والشبكة الإسلامية فعلياً، وعالج الحالة بحيث لا يتعطّل التشغيل بسبب CORS (مثلاً: عدم طلب crossorigin إلا عند الحاجة للتحليل، مع تعطيل المخطط البصري بأمان عند غياب CORS بدل كسر الصوت).
- **القبول**: التشغيل يعمل من كل المصادر المتاحة، ولا يظهر خطأ صامت.

## A5. لا ملف رخصة (LICENSE)
- **المشكلة**: أصول من أطراف ثالثة (صور ويكيبيديا/Commons، صفحات مصحف CC-BY-NC، أذكار rn0x/Adhkar-json، أذان mohsalvi/adhan-audio) بلا `LICENSE` ولا إشعارات.
- **المطلوب**: أضف `LICENSE` للمشروع + ملف `NOTICE`/قسم إشعارات يوثّق مصادر الأصول ورخصها، وحدّث README.

## A6. كود/أصول ميتة
- `src/data/live.json` غير مستورد في أي مكان — احذفه أو فعّل الميزة الموعودة.
- مجلد `/img` في جذر المستودع نسخ مكرّرة من صور موجودة في `public/img` — احذفه.
- لا تبنِ ملفات mp3 الخاصة بالأذان داخل الحزمة إن لم تكن لازمة إلا عند الطلب؛ قلّل وزن البناء (‏≈6MB حالياً) عبر تحميلها كسولاً.

## A7. تناقض الوثائق
- `docs/ROADMAP.md` يقول «single-file vanilla … no build step» وهذا مخالف للواقع (Astro + build). صحّح الوصف وحدّث حالة المراحل، ووثّق بدقة ما نُفّذ فعلاً وما لم يُنفَّذ.

## A8. الأذكار — تقدّم غير محفوظ
- **المشكلة**: `akTap()` يعدّل DOM فقط، ولا حفظ للتقدّم اليومي، ولا اختيار تلقائي لتبويب صباح/مساء.
- **المطلوب**: احفظ التقدّم يومياً بمفتاح `ouns_adhkar_YYYY-MM-DD` يُصفَّر تلقائياً في اليوم التالي، واعرض «تم X/Y»، واسترجعه عند إعادة الفتح، واختر تبويب صباح/مساء تلقائياً حسب الوقت (قابل للتجاوز).

## A9. المواقيت والأذان — نواقص
- نفّذ وضع الأذان `duck` (خفض صوت التلاوة) بحيث لا يُلغى المطلوب في B4 (انظر أدناه للسلوك المطلوب عند الأذان).
- أضف إشعار سطح المكتب الاختياري عبر Notification API عند دخول الوقت.
- ثبّت مصدر تحديد الموقع/المدينة بشكل موثوق وأضف قائمة مدن بديلة ثابتة عند فشل التحديد.

## A10. بنية الكود
- فكّك `app.js` تدريجياً إلى وحدات منطقية (state / api / player / mushaf / prayer / adhkar / ui) مع الحفاظ على السلوك، وأضف ESLint + Prettier، وأضف `engines` في `package.json`.
- أضف اختبارات أساسية للوحدات الحرجة (اختيار المصدر، بناء الروابط، حساب الصف/الجزء، صيغة العدّاد، تحويل الأرقام العربية).

## A11. تكرار CSS وازدواج المعالجات
- `global.css` يحتوي أقساماً مكرّرة من ترحيل Astro (‏«mushaf fullscreen» مرتين، «mobile responsiveness» مرتين، وقسم «RESTORED BASE COMPONENTS lost in Astro migration»). وحّدها واحذف التكرار الميت.
- يوجد **معالجا `click` منفصلان** على `#view` في `app.js` — ادمجهما في نقطة تفويض واحدة منظّمة.

## A12. خطأ منطقي في `markPlayingRows()`
- عند إزالة تمييز صف «مجموعة» يصبح الرقم `null` فيُكتب `<b></b>` وتضيع بيانات السورة. أصلح الاستنتاج، وأزل العبارة العبثية `(row.dataset.coll!=null?null:null)`.

## A13. طبقة API خارجية موحّدة
- يوجد اعتماد على ≈10 واجهات خارجية بلا طبقة تجريد أو كاش موحّد. أنشئ طبقة واحدة (`apiFetch`) بزمنٍ مهلة، وإعادة محاولة، وكاش بسيط، ومعالجة أخطاء موحّدة.
- **Nominatim**: أضف `User-Agent` تعريفي والتزم بسياسة الاستخدام (حد المعدّل) وإلا استخدم بديلاً.

## A14. Service Worker
- اسم الكاش ثابت `ouns-v1` بلا ترقية → خطر تقديم ملفات قديمة. أضف نسخ/إصدار وإبطالاً صحيحاً.
- أضف تخزيناً مؤقتاً مناسباً لصفحات المصحف المحلية بحيث تعمل دون اتصال، واستثنِ ما يجب استثناؤه.

## A15. التدويل والـ SSR
- الصفحة تُبنى دائماً بـ `lang="ar" dir="rtl"` وتُغيَّر بـ JS لاحقاً → وميض للغة الإنجليزية وفهرسة خاطئة. اضبط `lang/dir` الصحيحين عند البناء/التحميل بلا وميض.
- أضف ترجمات ناقصة: عناوين/أسماء يوتيوب (`YT_LIST`)، أصوات الأذان، أسماء فئات الأذكار، وتذييل الشريط الجانبي (`أُنس · رفيق التلاوة` مكتوب مباشرة).

## A16. SEO/PWA
- أضف `sitemap.xml` (تكامل Astro) واربطه في `robots.txt`، وأضف `screenshots/` و`shortcuts` في manifest إن أمكن.

## A17. الوصولية (a11y)
- أشرطة التقدّم عناصر `div` بلا أدوار — أضف `role="slider"`/`aria-valuenow/min/max` أو استخدم عناصر أصلية.
- أضف `:focus-visible` واضحاً لكل العناصر التفاعلية (يوجد `outline:none` بلا بديل في مواضع عدة).
- وحّد `aria-label` مع مفاتيح الترجمة، وتأكّد من تسمية كل زر أيقوني.

## A18. أمان العرض
- راجع كل `innerHTML` الذي يستهلك بيانات API (خصوصاً `prayerCardsHTML`) وهُرِّب كل الحقول النصية (`readable`, `hijri`, …) عبر `esc()`.

## A19. الخطوط
- انقل خطوط Google (Alan Sans / Amiri) إلى الاستضافة الذاتية لتحسين الأداء والخصوصية والعمل دون اتصال (خط أسماء السور مُستضاف أصلاً).

# المرحلة ب — تحسينات التجاوب والتجربة

## B1. التجاوب لكل الشاشات — عنصر بعنصر
- **المطلوب**: جولة تجاوب منهجية تغطّي **كل عنصر واجهة** عبر كامل المقاسات: هاتف صغير (≤360px)، هاتف (361–480)، هاتف كبير/تابلت صغير (481–768)، تابلت (769–1024)، لابتوب (1025–1440)، شاشات كبيرة (≥1441)، ووضع العرض الأفقي (landscape) منخفض الارتفاع.
- **العناصر الواجب مراجعتها فرداً فرداً**: `#bgFx`، الشريط الجانبي والبحث والـ topbar، الشبكة الرئيسية والهيرو (`hero`, `hero-side`, `hp-card`)، شبكات القرّاء والسور وقوائم المجموعات، تفاصيل السورة، المصحف (الغلاف/الصفحة/الشريط العلوي/الفوتر/السلايدر) والعرض بصفحتين على الديسكتوب، لوحة now-playing وكل وضعياتها، فوتر المشغّل بكل أزراره، المشغّل بملء الشاشة، النوافذ المنبثقة (الإعدادات/المواقيت/الجودة/التأكيد/الدرج)، بطاقة الطقس/المواقيت في الهيرو، صفحات المواقيت والأذكار ويوتيوب وبطاقات تلاوات يوتيوب.
- **القبول**: لا تمرير أفقي غير مقصود في أي مقاس، لا عنصر مقصوص/متراكب/خارج الشاشة، ولا ازدحام أو فراغ مفرط، مع الحفاظ على اتجاه RTL في كل المقاسات.

## B2. بطاقة «يُتلى الآن» للهاتف — ملتصقة فوق فوتر المشغّل
- **السياق الحالي**: عند `max-width:1280px` تُخفى `.np-panel` تماماً (`display:none !important`) ولا يوجد بديل — أي أن الهاتف يفقد الوصول للوحة الآن-يُتلى.
- **المطلوب**: صمّم **بطاقة now-playing مخصّصة للهاتف** تتثبّت أعلى فوتر المشغّل مباشرةً (`bottom: var(--player)`)، وتظهر تلقائياً عند وجود مقطع قيد التشغيل:
  - الحالة المطويّة (افتراضية): صورة/غلاف مصغّر + اسم السورة والقارئ + شريط تقدّم رقيق + زر تشغيل/إيقاف + زر التالي + زر توسيع.
  - عند النقر: تتوسّع إلى مشغّل ملء الشاشة الحالي (`#npOverlay`) وتُخفى البطاقة.
  - لا تغطّي المحتوى: أضف هامشاً سفلياً مناسباً لمنطقة المحتوى يساوي ارتفاع البطاقة + المشغّل.
  - احترم منطقة الأمان (`env(safe-area-inset-bottom)`) وارفع البطاقة فوق الشريط عند الحاجة.
  - حافظ على سلوك الديسكتوب كما هو (اللوحة الجانبية/العائمة).
- **القبول**: على الهاتف تظهر البطاقة ملتصقة فوق الفوتر، سلسة، بلا تراكب، وتتحول إلى ملء الشاشة عند النقر، وبلا تأثّر أداء.

## B3. المقاسات (خطوط/حشوات/مسافات) لكل الشاشات
- **المطلوب**: أنشئ سلم مقاسات موحّد (type scale + spacing scale) اعتماداً على المتغيّرات، طبّقه على العناوين الفرعية/الرئيسية والنصوص والأزرار والشرائح والبطاقات والشرائط، وصولاً إلى الخطوط الدقيقة والبادجات.
- استخدم وحدات مرنة (`clamp()` / `rem` / متغيّرات) بدل القيم الصلبة المتفرّقة، وضبط الحشوات والفواصل (gap) في كل breakpoint.
- **القبول**: تناسق بصري عبر كل المقاسات، لا نص أصغر من الحد المقروء، ولا عناصر مزدحمة أو متباعدة زائداً.

## B4. الأذان يجب أن يوقف **كل** المشغّلات (سلوك مطلوب)
- **المشكلة الحالية**: الأذان يعمل لكن **التلاوة الحالية لا تتوقف**.
- **السلوك المطلوب**: عند حلول وقت الصلاة ورفع الأذان → يُوقف/يُلبَّت **كل مشغّل صوت** دفعة واحدة:
  - إيقاف تشغيل `audio` (المشغّل القرآني).
  - إيقاف مشغّل يوتيوب (`ytPlayer.pauseVideo()` إن وُجد).
  - إيقاف/تجميد الرسوم المتحركة المرتبطة بالتشغيل (موجات المشغّل) وتحديث الأزرار إلى حالة الإيقاف.
  - منع تشغيل أي مشغّل آخر أثناء الأذان، والسماح بالإيقاف اليدوي للأذان (الزر الموجود).
- **سؤال يجب جوابه في التنفيذ**: هل الخلل ناتج عن أن `playAdhan()` لا يستدعي إيقاف المشغّلات إطلاقاً، أم أن هناك تشغيلاً متزامناً في مكان آخر؟ شخّص السبب بدقة ثم أصلحه، ولا تكتفِ بإخفاء العَرَض.
- **القبول**: عند بدء الأذان يكون `audio.paused === true` ومشغّل يوتيوب متوقفاً، وتُعكس الحالة بصرياً، ولا يبدأ مشغّل القراءة تلقائياً حتى نهاية الأذان.

## B5. تدوير المندالا سريع جداً على اللابتوب — إصلاح bug
- **السياق**: الحركة معرّفة في `global.css`:
  - `.mandala-svg .spin-a { animation: spin 90s linear infinite }`
  - `.spin-b { … 70s … reverse }` و`.spin-c { … 120s … }`
  - وتُوقف عند عدم التشغيل عبر `body:not(.playing) .mandala-svg .spin-*`.
- **الملاحظة**: المستخدم يرى سرعة دوّار مرتفعة جداً على اللابتوب رغم أن المدد طويلة.
- **الفرضيات الواجب التحقق منها ثم الإصلاح**:
  1. غياب `transform-box: fill-box` و`transform-origin: center` يجعل التدوير حول أصل الـ SVG (زاوية) لا المركز → مظهر «دوران سريع/غريب». صحّح ذلك.
  2. إعادة بناء الـ SVG عبر `innerHTML` بشكل متكرّر تُعيد تشغيل الأنيميشن فيبدو كقفزات/تسارع. تجنّب إعادة التوليد غير الضرورية وأعد استخدام العناصر حيث أمكن.
  3. قد يؤثر وجود عدة نسخ للمندالا متزامنة. تأكّد من الاتساق.
  4. احترم `prefers-reduced-motion` (وقف التدوير) كما تفعل مع الأورورا، واربط الحالة بحالة التشغيل.
- **المطلوب**: احرص على أن يكون التدوير بطيئاً وسلساً ومتمركزاً ومتّسقاً بين الأجهزة (ويُفضَّل قيادته بزمن متراكم عبر rAF لتفادي فروق معدّل التحديث)، مع `will-change` مناسب وعدم استهلاك بطارية/معالج زائد.
- **القبول**: سرعة الدوران بطيئة ومتساوية بصرياً على اللابتوب والهاتف، وتتوقف عند عدم التشغيل ومع `prefers-reduced-motion`.

## B6. تباين النصوص مع الخلفيات
- **المشكلة**: تفاوت في التباين بين النصوص والخلفيات في الوضعين (مثال مواضع تحتاج فحصاً: النص الثانوي `--ink2` على الأسطح، الذهبي `#B99745` كنص/بادج على الخلفيات الفاتحة، البادجات والشرائح، النص فوق صفحة المصحف وأشرطته، بطاقات المواقيت، `--gold2` في الوضع الداكن، والشارات الصغيرة).
- **المطلوب**: راجع أزواج (نص/خلفية) لكل المكوّنات في **الوضعين الفاتح والداكن**، واحقّق **WCAG AA** على الأقل: ≥4.5:1 للنص العادي و≥3:1 للنص الكبير/الأيقونات. أصلح الأسباب في متغيّرات الألوان الأساسية (`:root` و`[data-theme="dark"]`) بدل ترقيع كل عنصر على حدة.
- **القبول**: كل نصوص الواجهة في الوضعين تجتاز AA، بلا تغيير في الهوية اللونية العامة.

## معايير القبول العامة
- البناء ينجح: `npm install && npm run build` بلا أخطاء/تحذيرات حرجة.
- اختبار يدوي موثّق على المقاسات: 360 / 390 / 768 / 1024 / 1440 / 1920 ووضع landscape منخفض الارتفاع، بالعربية والإنجليزية، وفي الوضعين الفاتح والداكن.
- لا تراجع لغوي (ar/en) ولا تراجع RTL، ولا كسر لأي ميزة قائمة.
- للعناصر التفاعلية حالات `focus-visible` واضحة، والنوافذ قابلة للإغلاق بلوحة المفاتيح (Esc).
